# 抖音续火花 2.9

基于 Python、FastAPI 和 Playwright 的单账号本机工具，提供联系人同步、火花状态查看、勾选台账、手动运行、定时任务和网页内扫码登录。

**当前源码为 2.9，首次创建配置时默认启用密码门。各启动入口检查缺失密码；已有认证开关和有效密码保持原样，默认只监听本机回环地址。** 不支持通过公网域名、局域网、反向代理或隧道共享控制台。扫码任务自己的临时校验仍然保留，用于避免不同扫码任务相互干扰。

发布源码不包含个人配置、Cookie、好友名单、发送记录、日志或运行备份。首次运行后生成的这些文件属于使用者自己的私有数据。

## 每日可用性更新（2026-10-26）

目标是“每天真的续上”，同时保留当天的防重复保护：

- **防重复保护只管当天。** 待核对、页面明确拒绝、台账恢复保护和数据恢复后的后台暂停，都只在发生当天阻止发送；过了零点（Asia/Shanghai）自动失效，第二天照常发送。日期无法判断的旧记录仍按当天处理，需要在页面上核对。
- **卡住的状态都有出口。** “好友”页新增“发送结果待核对”区：在抖音看到消息就点“在抖音看到了，记为已发”，确认没发出就点“确认没发出，允许重发”。台账恢复保护可点“我已核对，解除发送保护”；次日也会先用可读的备份修复主台账（损坏原件改名为 `ledger.json.corrupt-*` 保留），再把保护标记改名留档。
- **每日自动续火花由网页开关控制。** “定时”页的开关可直接切换，打开后立即启动后台任务，并补上当天错过的一次，无需重启。启动脚本不再强制暂停；`.env` 里的 `SPARKKEEPER_BACKGROUND_TASKS` 留空表示跟随网页开关，写 `0`/`1` 则强制关闭/开启。
- **发送确认适配真实抖音页面。** 实测真实页面没有测试用消息标记，`[续火花吧]` 会渲染成表情图片，而且发送后左侧会话列表会重排、替换选中行节点，旧判据因此每次都记“待核对”并停下整轮。现在按真实结构确认：发送后出现序号（`data-index`）更大的己方消息行（类名含 `isFromMe`），且没有失败或发送中标记，就记为已发出；发送后只要求右侧标题、输入框和会话区不变，左侧选中项允许重排，但最终确认时必须仍是目标好友。仍无法确认时，日志会写明诊断代码（`scope_changed`、`no_new_message`、`new_message_pending_or_failed`、`input_not_cleared`、`read_error`）。其次才核对与文案相同的文字；只看输入框清空的宽松兜底默认关闭，见下文“发送确认”。
- **按“新出现的最底一行”确认，不依赖序号方向。** 发送前记下会话里已有的消息行；发送后最底下一行若是新出现的己方消息、且没有失败或发送中标记，就记为已发出。仍无法确认时，在私有数据目录写 `delivery-after-send.json`，只含发送前后各消息行的序号和状态（是否己方、是否新出现、是否失败或发送中），不含文字、好友名或消息编号。
- **一位待核对不再拖住整轮。** 会话校验一直正常、只是没看到新消息时，继续发下一位（每位发送前都会重新定位并严格核对会话）；会话被切走、读取异常、页面明确拒绝或发送意图写入失败时，仍停下本轮。
- **先等会话列表稳定再定位。** 实测抖音打开私信页后会先显示一份临时会话列表，约 1～4 秒后才换成真实列表；程序过去在临时列表出现时就开始排序和定位，第一位好友必然找不到。现在要等会话标题连续 3 秒不变（最多等 20 秒）再开始。
- **搜索兜底结束后清空搜索框。** 过去搜索失败后名字留在搜索框里，左侧列表一直停在搜索结果，后面的好友会全部“找不到”。
- **定位滚动与好友同步一致。** 会话列表是固定高度的虚拟列表（一次只渲染十几行），定位使用与好友同步相同的滚动容器与到底判据，到底后再等一会儿确认高度不变。
- **定位失败有诊断日志。** 未能切换到好友会话时，日志记录点击后左侧选中、右侧标题哪一项没对上，以及列表遍历和搜索兜底的结果。
- **日志时间改为本地时间。** Windows 不认识 `.env` 里的 `TZ=Asia/Shanghai`，会把日志时间记成 UTC（慢 8 小时）；现在在 Windows 上忽略这一项，业务日期仍固定按 Asia/Shanghai 计算。
- **只在需要你处理时发邮件。** 当天出现待核对、明确拒绝或恢复保护时，每天最多提醒一封；原有的登录失效、0 成功和连续失败告警保留。
- **开机自启（可选）。** 双击 `设置开机自启.bat`，登录 Windows 时自动最小化启动控制台；双击 `取消开机自启.bat` 取消。脚本只为当前用户注册一个登录任务，不改其它系统设置。

## 2.9 的主要变化

- 默认启用管理密码门；已有配置保持原样，Windows、Linux 源码入口及桌面入口在组件检查通过后补齐缺失访问密码。
- 统一页面、服务状态和启动说明的版本号。
- 修复同步时头像地址变化导致的历史重复记录；默认展示本次观察到的好友，历史记录可按需显示。
- 正常火花、重燃中和即将消失的好友纳入火花筛选及一键勾选；无法可靠读取的状态不会自动当作零天。
- 概览和凭证状态颜色更明确，说明文字更清楚；缩小扫码与结果区域，保留四阶段扫码过渡和邮箱收展效果。
- 动态背景根据实际流畅度调整像素预算和绘制频率，保留原有纹理、暂停开关及最高 120 帧目标；设备负载较高时优先保证页面操作流畅。

## Windows 源码运行

需要 Python 3.10 及以上。将完整项目放在可写目录中：

1. 双击 `安装依赖.bat`。它创建本项目的虚拟环境，按 `requirements.lock` 安装依赖并下载 Chromium；此步骤需要网络。
2. 双击 `启动单账号本机版.bat`。
3. 在浏览器打开 <http://127.0.0.1:8000/>，输入访问密码进入控制台。
4. 在“凭证”页点击“开始扫码登录”，用本人抖音 App 扫码并确认。二维码显示在当前网页内，成功后自动保存本机凭证。
5. 同步好友、核对火花状态并保存勾选。先用“模拟演练”检查定位流程，再自行决定是否正式发送。

后台定时发送、自动采集、预热和体检跟随网页“定时”页的“每日自动续火花”开关：关闭时只能手动发送，打开页面本身不会触发发送。停止时在启动窗口按 `Ctrl+C`。

若端口 8000 已被其他实例占用，先确认并停止原实例；不要让两个实例共享同一个数据目录。虚拟环境损坏时，重新运行安装脚本。安装器会保留失效环境的重命名副本，不会删除账号数据。

## Linux 本机运行

需要 Python 3.10 及以上、venv 支持和 Chromium 所需系统库。在项目目录执行：

```sh
bash start.sh
```

脚本首次创建虚拟环境、安装锁定依赖和浏览器组件，检查通过后在终端隐藏输入访问密码，再仅监听 `127.0.0.1:8000`，后台任务默认暂停。已有有效密码不会重复设置；取消或初始化失败不会启动服务。无交互终端时不会回退到明文密码输入，应先在本机终端完成设置。如果系统提示缺少 Chromium 依赖，请按 Playwright 的安装提示补齐系统库后重试。

`deploy.sh` 仅保留为本机启动兼容入口，不安装系统服务、不开放端口、不配置反向代理。`douyin-streak.service` 是可选的本机服务示例，路径和运行账号需由使用者自行准备；默认同样暂停后台任务。

## 日常使用与结果含义

- **勾选草稿需要保存。** 保存后的名单才是发送任务使用的名单；未保存时先保存或放弃草稿。
- **同步完成以当前任务结果为准。** 旧台账人数不代表本次同步成功；“本次未观察到”不等同于好友已删除。
- **历史重复整理保持保守。** 只按受支持的头像资源与身份条件合并可确认重复的记录，保留原勾选和发送历史；不同身份或待核对记录不会仅凭昵称合并。
- **同名好友不猜测。** 页面不要求逐个确认“是否同一人”，但真实身份歧义仍会阻止自动选错会话。必要时先在平台设置可区分备注，再重新同步。
- **已确认接受不等于已读或火花必然增长。** 系统核对本次新消息及失败信号；证据不足会标为“待核对”，当天不会自动重发。请在抖音核对后到“好友”页点对应按钮；不核对的话，第二天照常发送。
- **当天去重与待核对保护保留。** “继续未完成”只处理符合重试条件的待处理对象，当天不自动重发已成功、已拒绝或待核对的消息。
- **旧台账备份不能证明消息未发送。** 主台账缺失或损坏、需要读取备份时，会在数据目录写入 `ledger-recovery-required.json`，当天暂停发送；同步、保存勾选、重启及强制发送都不会解除它。核对当天发送历史后可点“我已核对，解除发送保护”；次日会自动修复并解除。主备都无法读取时保持保护，需先重新同步好友生成新台账。
- **模拟演练不发消息。** 它检查页面定位流程，并在结果 `delivery_checks` 中记录是否观察到带标识的己方历史消息。`observed` 只表示看到了历史页面标记；空会话、缺少标记、读取异常或存在失败/待发送信号时记录为 `unverified`（未验证），不据此判定平台不支持。页面没有消息标记、但己方一侧有与本次文案完全相同的历史消息时记为 `historical_text_observed`，表示正式发送可以用文字证据确认。演练同时把当前会话区的结构摘要（标签、class 名和 `data-*` 属性名的出现次数）写入私有数据目录的 `delivery-probe.json`，用于适配真实页面。诊断不保存消息正文、好友名或消息 ID，也不能替代真实投递或平台火花增长的验证。
- **凭证保存不等于始终有效。** 凭证页同时显示上次检查状态与时间，失效后可重新扫码更新。
- **定时页展示生效配置。** 文案、执行时间和发送间隔等固定字段只读；“每日自动续火花”开关可直接切换。`.env` 把 `SPARKKEEPER_BACKGROUND_TASKS` 设为 `0`，或数据刚从备份恢复的当天，开关打开也不会启动后台任务，页面会提示原因。
- **发送确认。** 优先认带标记的新消息；页面没有标记时，认本会话己方一侧新增的、与文案完全相同的消息。若模拟演练显示真实页面读不到消息文字（例如文案被渲染成表情图），可在 `.env` 设 `DELIVERY_ACCEPT_INPUT_CLEARED=on`：按下发送后输入框清空，且持续 `INPUT_CLEARED_QUIET_SECONDS`（默认 3）秒没有任何失败提示，就记为已发出。这个兜底可能把少数没发出的消息记成成功，默认关闭。

## 配置与数据

首次创建配置默认启用管理认证；Windows、Linux 启动脚本会在隐藏输入中设置缺失密码，桌面入口使用隐藏字符的输入窗口。已有有效密码和认证开关保持不变。可选配置参见 `.env.example`；源码运行默认使用项目根目录 `.env`，打包后默认使用 EXE 同级 `.env`，也可通过 `ENV_FILE_PATH` 指定已有文件，初始化与服务读取同一位置。自定义路径的父目录需事先存在。账号数据默认写入 `data/`，不会因密码初始化而清理或重置。这些默认路径已被 Git 忽略。

本机启动入口从所选配置文件读取四个认证凭据字段，避免继承旧进程密码；其它环境变量仍按原有优先规则生效。源码直接运行 `app.py` 不执行交互式初始化，使用前应先在终端运行 `python password_setup.py`。

请妥善保管以下私有资料，不要随源码上传或分享：

- `.env` 和邮箱授权码；
- `data/state.json` 等浏览器登录态；
- 好友、消息和发送台账；
- 日志、截图、诊断结果及 `data/backups/`。

备份与升级前先停止任务和服务。不要把使用过的工作目录直接压缩发布。项目提供 `tools/make_release.py` 按白名单导出源码，默认排除私有配置、数据、日志、构建产物和 Git 历史。

测试快照、发布目录和 ZIP 都会检查允许导出的文本，发现硬编码管理令牌、邮箱授权码、Cookie 导出或私钥标记会停止；测试文件、文档和生成报告同样检查。错误只显示相对文件名、行号与问题类型。合成用例使用明确的 `synthetic-` / `fixture-` 占位值；必须保留的固定测试向量可在同一行声明该值的 `SYNTHETIC_SECRET_SHA256`，声明只对该测试值生效。扫描用于拦截常见泄漏形态，不能代替发布前核对，也不能保证发现经过编码隐藏的秘密。

历史重复整理工具默认只预览：

```sh
python tools/consolidate_contacts.py --data-dir data
```

确认预览后才使用 `--apply`。工具会检查运行占用并先备份原台账，保留可恢复的合并报告；有运行任务或待派发队列时会拒绝写入。

### 私有数据备份与恢复演练

先停止服务，再使用项目虚拟环境中的 Python。下面的 `backups` 父目录需事先创建；输出文件必须尚不存在，并位于数据目录之外：

```sh
python tools/data_backup.py backup --data-dir data --output backups/private-data.zip
python tools/data_backup.py verify --archive backups/private-data.zip
python tools/data_backup.py restore --archive backups/private-data.zip --target data-restored
```

工具只收集数据目录中的 `config.json`、`ledger.json`、`ledger.json.bak`、`runtime.json`、`state.json` 及恢复保护标记，逐文件记录字节数和 SHA-256；不读取 `.env`、日志、截图或目录外的登录态。使用 `STATE_FILE_PATH` 的外置凭证需要另行保管。**这是包含登录态及好友记录的私人备份，未加密，不应上传 GitHub 或随源码分享。** SHA-256 用于发现损坏和摘要不一致，不是备份来源的数字签名。

备份与服务使用同一把操作系统锁。若部署使用了自定义 `INSTANCE_LOCK_PATH`，必须额外提供 `--lock-file`，值是该 PID 路径后追加 `.lock` 的实际锁文件，例如 `--lock-file D:/private/server.pid.lock`。工具不会读取 `.env` 猜测这个路径。

恢复只接受**尚不存在的新目录**，不覆盖原数据，也不接受已存在的空目录。任何备份都可能遗漏备份生成后的发送，因此恢复后都会启用 `ledger-recovery-required.json` 和 `restore-paused.json`：恢复当天后台任务保持暂停，继承的后台开启环境变量也不会绕过；手动、强制发送同样受发送历史恢复保护。已有损坏标记按原字节保留，勾选、发送历史及待核对意图一并保留；保护以标记内容时间和文件写入时间中较晚的那天为准，因此从备份还原的旧标记在恢复当天同样生效。核对当天发送历史后，可在控制台点“我已核对，解除发送保护”；第二天两个标记都会自动失效，不会让火花因一次恢复而长期中断。不要通过删标记或强制发送绕过当天的核对。

工具在临时合成数据上完成过恢复演练；这不能证明任何一份个人备份已经实际演练成功。文件大小、白名单、摘要或内容结构不符时拒绝恢复。中途磁盘写入失败或进程退出可能留下新建的部分恢复目录，保护标记会先于账号数据落盘；该目录不能当作完整恢复结果，请保留保护并选择另一个新目录重试。源数据和旧备份不会被覆盖。

## 开发与验证

使用锁定依赖，避免用本机账号验证自动发送修改。测试应使用临时数据目录、本地模拟页面和虚构凭据。`tests/_isolation.py` 让整套测试默认使用临时数据目录，并且不读取真实 `.env`：`tests/test_00_isolation.py` 按文件名最先加载；在模块层导入项目代码的测试文件也在开头导入它，单独运行时同样不会写入真实 `data/` 或日志。

```sh
python -m unittest discover -s tests -p "test_*.py"
node tests/test_silk_background.cjs
node tests/test_qr_step_motion.cjs
node tests/test_console_status.cjs
```

Python 测试覆盖自有的来源校验、任务协调、发送状态与数据保护。前端测试覆盖扫码恢复、勾选草稿、状态展示和动画生命周期。隔离测试通过不代表真实抖音页面永远不变，也不代表消息一定送达。

桌面源码构建说明见 [desktop/README.md](desktop/README.md)。仓库源码可运行不等于 Windows 安装包已完成实机验收。
