### 发送与模拟演练异常修复（2026-10-12）

修复常驻浏览器复用时丢失上下文管理器的问题：冷启动转为常驻后同时保留生命周期所有者，显式关闭时统一退出，避免页面对象还在、Playwright 却被垃圾回收关闭。

浏览器／驱动已经关闭时，本轮明确报告系统中断，不再把它转换成连续的“找不到好友”。尚未处理的联系人保留为待处理，已经成功或明确跳过的联系人不会重新列入补发。模拟演练不会真实发送消息，也不会安排真实自动补发；模拟定位结果不再修改好友的匹配确认或会话路由元数据。

如果已经尝试按 Enter，但页面未能确认结果，会单列为“待核对”，不原地重发，也不自动补发该好友；其余尚未尝试的目标保留为待处理。

结果统计同时兼容字符串形式的成功项和字典形式的失败项，修正完成数少算；概览页区分模拟演练与实际发送，并显示系统中断及待处理数量。

专项隔离回归：

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -p "test_send_browser_lifecycle.py" -v
.\venv\Scripts\python.exe -m unittest discover -s tests -p "test_browser_errors.py" -v
.\venv\Scripts\python.exe -m unittest discover -s tests -p "test_send_results.py" -v
```

更新服务后，建议先对同一批好友运行“模拟演练”，确认定位结果，再由使用者手动发起实际发送。历史失败记录保留；本次修复的隔离回归不代表真实平台发送已经完成。

### 黑金玻璃与步骤动效（2026-10-12）

凭证页使用通透黑金玻璃，两张卡片悬停时保持同一底色，文字区域有稳定的深色遮罩。全站背景改成原生 WebGL 绘制的柔和香槟金丝绸；顶部开关可暂停或恢复，偏好仅保存在当前浏览器。

1—4 步由真实扫码状态驱动，高亮每段用 420 毫秒向右平滑移动。后端直接返回完成时，视觉依次滑过已确认步骤；没有新的服务端确认不会自行推进，状态文字始终保留真实结果。成功时出现一次勾选动效，二维码图片和面板框架保持稳定。

桌面绘制上限目标为 120 FPS，实际帧率受显示器、浏览器和设备能力限制；手机目标 30 FPS 并降低画布像素开销。隐藏页面、输入暂停和手动关闭会停止请求动画帧，恢复时不会突然跳过暂停期间的动画。系统开启减少动态效果时使用静态背景和即时步骤定位。

```powershell

```

模拟界面控制条提供“模拟扫码确认”“模拟保存中”“模拟完成”，可以逐步推进，也可从等待直接完成，验证连续右移。所有步骤均为虚构状态，不连接抖音。

状态提示面板与整体黑金主题统一：失败／冷却提示采用低饱和琥珀色，发送面板保留当前好友、成功／失败计数和真实进度，同时收紧桌面留白。细金色流光与图标轻呼吸只作用于装饰层，不修改真实进度；关闭动态背景或系统减少动态效果时，装饰动画暂停或关闭。

状态面板出现时用 480 毫秒柔和展开，退出时用 340 毫秒收回，底部布局同步移动；离场期间保留原有内容，普通进度更新不重新播放进入动画。框架不倾斜，系统减少动态效果时即时切换。

功能导航使用亮金底深色文字标记当前页面，未选中保持深色底浅色文字；悬停仅轻微提亮，并提供键盘焦点边框与当前页面语义，桌面侧栏和手机底栏一致。

六个导航按钮的金色选中背景柔和展开，取消选中时平滑淡出收回；按钮框架、图标和文字保持平直，快速切换从当前状态自然衔接。页面切换保留原有行为，系统减少动态效果时按钮即时切换。

## 项目说明

这是单账号控制台，可直接打开面板，无管理员登录门；抖音账号仍需由本人扫码登录。
支持 Windows 源码启动与桌面构建，也可安装为 Linux 本机 systemd 后台服务。
后端始终监听回环地址，默认在本机使用；也支持显式配置访问来源后，由同机 Nginx 反向代理。
通过域名访问时，使用者需自行限制后台访问范围。

## 本机启动

Windows 先准备 Python 3.10+ 与项目虚拟环境：

```powershell
python -m venv venv
.\venv\Scripts\python.exe -m pip install -r requirements.lock
.\venv\Scripts\python.exe -m playwright install chromium
```

然后双击 `启动单账号本机版.bat`，在同一台电脑打开
`http://127.0.0.1:8000/` 即可进入控制台。
本机 BAT 设置 `SPARKKEEPER_BACKGROUND_TASKS=0`，默认暂停后台定时任务；
手动操作入口保留，请先使用模拟演练确认定位结果。

Linux 本机手动启动：

```bash
bash start.sh
```

脚本会准备虚拟环境与 Chromium，随后启动回环服务。无需先填写任何面板凭据。
除本机 BAT 外，其他启动入口的后台任务沿用既有开关与配置，不强制暂停。
`.env` 仅用于 SMTP、浏览器等可选设置；没有邮件需求时可以保持模板中的空值。

## 可选：Linux 本机后台服务

在准备运行服务的那台 Linux 电脑上执行：

```bash
sudo bash deploy.sh
```

脚本把程序安装到 `/opt/douyin-streak`，保留该机器的
`data/`、可选 `data/service.env`、虚拟环境与浏览器缓存，安装 systemd 服务。
服务默认监听 `127.0.0.1:8000`，后台任务遵循既有开关与配置；在运行服务的同一台电脑
打开本机地址使用面板。自动拉起由 systemd 提供。

如需通过域名访问，在 `/opt/douyin-streak/data/service.env` 中设置完整的外部来源，
例如 `QR_PUBLIC_ORIGIN=https://example.com`，然后重启服务。来源必须包含协议、主机和
实际使用的非默认端口，不带路径、查询参数或末尾斜杠；它必须与浏览器地址栏的来源一致。
保持后端 `HOST=127.0.0.1`，按照 `extra/nginx.conf.example` 配置同一台机器上的 Nginx，
替换示例域名和证书路径。安装脚本只安装本机 systemd 服务，不会配置 Nginx 或证书。

反代需保留请求的 `Host`，将 `X-Forwarded-Proto` 设置为外部请求协议，
并用实际客户端地址覆盖 `X-Forwarded-For`。后端只信任来自回环地址的代理连接，
扫码写接口还会核对已配置的来源和浏览器 `Origin`；配置来源不会增加管理员登录门。
请自行通过网络或代理访问范围限制保护后台。留空 `QR_PUBLIC_ORIGIN` 时继续按本机方式使用。

常用本机服务命令：

```bash
systemctl status douyin-streak
journalctl -u douyin-streak -f
sudo systemctl restart douyin-streak
sudo systemctl stop douyin-streak
sudo systemctl start douyin-streak
```

## 文件与个人数据

- `app.py`、`core/`、`routers/` 和 `static/` 是程序源码与本机面板。
- `.env.example` 是不含个人设置的模板；真实 `.env` 仅保存在使用者机器上。
- `data/state.json` 是抖音登录态；`config.json`、`ledger.json` 和日志可能包含个人账号与好友信息。
- 公开仓库和桌面构建不携带真实 `.env`、登录态、台账、日志或其他个人数据。

请只备份到自己控制的位置，不要把个人 `data/` 或 SMTP 授权码放入公开仓库和软件分发包。

## 面板主要功能

- **好友与消息**：同步联系人、勾选好友，查看发送配置。
- **定时与风控**：查看发送节奏与后台任务状态；本机 BAT 默认暂停，其他入口遵循既有开关与配置。
- **运行日志**：查看本机任务记录。
- **立即续火花**：手动触发；模拟演练不发送真实消息。

## 面板内扫码登录与自动保存

“凭证”页采用与 8003 版本相同的使用流程，并在本项目内独立实现：

1. 启动单账号服务，打开“凭证”页，点击“开始扫码登录”。
2. 二维码显示在当前面板中；登录浏览器在后台运行，不打开新窗口。
3. 使用本人抖音 App 扫码，并在手机上确认登录。
4. 后端同时检测已登录页面信号和有效会话 Cookie，通过后自动更新原来的
   `data/state.json`（设置了 `STATE_FILE_PATH` 时，只使用该指定文件）。
5. 旧预热浏览器会话失效，下一次发送从新登录态启动；无需导出文件或再次上传。

登录实现直接复制自本机 8003 项目的 `LoginDesktopManager`、身份识别函数和 Cookie
处理函数，保存在 `core/sparkflow_login/`；`manifest.json` 记录源文件及函数的 SHA-256。
`adapter.py` 只负责将原异步方法接入 8000 的现有面板和单账号 state 文件保存流程。
原登录类的入口、二维码获取、刷新和身份判定方法均保持原样。

8000 使用自己的 `data/qr-login-profile` 目录，不复制或共用 8003 的账号和浏览器
数据。适配层限制清理范围，并确认浏览器关闭后才允许清理登录凭据；浏览器配置和
资源缓存可以保留。正式登录态仍只在确认成功后更新原 state 文件。

扫码最长五分钟，支持刷新与取消。遇到抖音官方的点击或拖动验证时，当前登录框会
临时显示验证画面，由用户本人完成；通过后自动恢复二维码流程，不打开新窗口。
验证画面仅保存在内存中，点击与拖动绑定当前截图版本，不提供键盘、脚本或任意
网页控制接口。取消、过期或失败不会覆盖原登录态。发送任务忙碌时不会同时替换凭据。
只有前端得到二维码图片和脱敏状态，完整 Cookie 不进入页面、URL 或日志。

本机使用无需额外配置，也不依赖 8003 服务或 `17653` 本机助手。扫码写接口继续校验
同源请求和本次扫码的独立确认信息。经同机反代访问时，必须设置与地址栏完全一致的
`QR_PUBLIC_ORIGIN`，否则扫码请求会被拒绝；此设置只声明允许的来源，不是后台访问凭据。
Windows 默认优先使用已安装 Edge；也可用 `QR_LOGIN_BROWSER_CHANNEL` 选择浏览器。
`QR_LOGIN_NETWORK_MODE` 沿用源实现的 `auto`、`direct`、`proxy` 路由。
这些选项不修改 Windows 的网络或代理配置。

原手动上传入口保留。旧独立助手和 `COOKIE_EXTRACT_MODE` 兼容接口保留，但已不作为
面板的默认扫码入口，旧 `/api/credentials/extract` 仍返回 410。

验证命令应在不含真实 `.env`、登录态和账号数据的隔离源码副本中执行：

```powershell
.\venv\Scripts\python.exe -m unittest discover -s tests -v
node tests/test_qr_login_frontend.cjs
```

现有旧助手测试可继续独立运行。单元与界面行为测试使用虚构状态，不代表真实扫码或发信结果。

## 注意事项

- 运行程序的本机需要能访问抖音网页版。
- 首次部署会安装 Chromium 浏览器，需要约 500MB 磁盘空间
- 浏览器运行需要足够内存，建议本机至少预留 2GB 可用内存。
- 发送频率不要太高，避免触发抖音风控
